# Дизайн исправлений по результатам ревью

## Цель

Закрыть все замечания из `CODE_REVIEW.md` и привести код к единообразному Python-стилю, не расширяя функциональность файлового менеджера и не создавая второй публичный API.

## Ограничения

- Сохранить локальный CLI, SQLite через стандартный `sqlite3`, текущую модель данных и пользовательские сценарии из `docs/lab-1.md`.
- Сохранить GitHub Actions и локальный запуск того же workflow через `act` согласно `docs/lab-2.md`.
- Не добавлять ORM, web/API, сервер БД, совместимый фасад `FileManager` или миграционный framework.
- Все изменения оставить незакоммиченными в локальной ветке `review/code-quality-fixes`; не выполнять push.
- Для изменений поведения применять TDD: сначала наблюдаем ожидаемое падение теста, затем минимальное исправление.

## Выбранный подход

### Выбран: точечный полный набор

Исправить тестовый контракт, окружение разработки, style gate, типы на границах, очистку blobs, область глобальной блокировки disks и контейнерную изоляцию CI. Не перестраивать доменные сервисы без необходимости.

### Отклонён: только blockers и стиль

Не закрывает логические замечания об очистке blobs, блокировке disks и несоответствие CI требованиям лабораторной работы.

### Отклонён: широкий архитектурный рефакторинг

DTO/repository-слой, общий фасад и развитая иерархия enum увеличат код и число абстракций без требований или внешних потребителей.

## Изменения

### 1. Тестовый контракт и зависимости

- Удалить устаревшие тесты фасада `file_manager.manager.FileManager`.
- Перенести уникальные поведенческие сценарии на текущие сервисы/CLI; не дублировать уже покрытые сценарии `test_workflows.py`.
- Унифицировать тесты на pytest, отказавшись от `unittest.TestCase` и subprocess-тестов импорта, где достаточно обычного pytest.
- Объявить закреплённую test/dev-группу в `pyproject.toml` и `uv.lock`.
- Использовать одну команду pytest локально и в CI.

### 2. Стиль и типизация

- Добавить Ruff как единственный formatter/linter; включить базовые правила ошибок, импортов, bugbear и modern Python.
- Отформатировать только код проекта, тесты и небольшие CI Python-скрипты; исходные методички не трогать.
- Добавить точные return/parameter types на публичных функциях и границах сервисов.
- Для контекста CLI использовать типизированную структуру вместо произвольного `dict`; для формата документа — `Literal`.
- Не вводить DTO для каждой строки SQLite: `sqlite3.Row` остаётся внутренним представлением persistence-слоя.
- Заменить `BaseException` на `Exception`, сохранив cleanup через `finally`/context managers.
- Убрать повторяющееся построение сервисов из команд через небольшие helpers; не добавлять контейнер зависимостей.

### 3. Жизненный цикл blobs

- Восстановительную очистку orphan blobs выполнять только перед операциями, которые изменяют
  blobs; read-only команды не сканируют каталог.
- `Operation` явно отслеживает blobs, созданные текущей операцией, и blobs, которые нужно удалить после успешного commit.
- При rollback удалять только новые blobs текущей операции; при commit — только заменённые/удалённые старые blobs.
- Ошибка post-commit cleanup не должна выдавать доменную операцию за откатанную: пользователь получает отдельное сообщение о том, что изменение зафиксировано, но очистка не завершена; событие cleanup сохраняется, когда БД доступна.
- Аварийный orphan после завершения процесса удаляется восстановительной очисткой следующей
  операции, изменяющей blobs.

### 4. Получение сведений о дисках

- Проверить identity короткой операцией, затем освободить SQLite transaction и глобальный lock.
- Выполнить `getmntinfo`/`/proc/self/mountinfo` и `statvfs` без блокировки хранилища.
- Повторно аутентифицировать тот же неизменный session token и записать аудит короткой операцией.
- Если сессия была заменена или завершена во время системного I/O, не приписывать действие новому пользователю; вернуть отказ текущему вызову.

### 5. CI в контейнерах

- Build, Test и SAST выполнять через закреплённый Docker-образ Python внутри jobs, сохранив существующий DAG и артефакты.
- Image/Publish оставить минимальными jobs с Docker daemon: Image собирает и проверяет образ, Publish только загружает проверенный artifact и публикует его.
- Сохранить совместимость workflow с `act`, кэшем и artifact server.
- Не передавать Docker socket в Build/Test/SAST.

### 6. Документация

- README должен описывать реальную команду установки dev-зависимостей и запуска pytest/Ruff.
- `docs/ci.md` должен точно описывать контейнерные jobs и единый тестовый набор.
- `CODE_REVIEW.md` сохранить как исходный отчёт, добавив статус устранения замечаний без переписывания истории ревью.

## Проверка

- Отдельные regression-тесты для targeted cleanup, rollback/commit cleanup и смены сессии во время сбора дисков.
- Полный pytest из чистого `uv sync --frozen --group dev` окружения.
- Ruff check и format check.
- Сборка wheel/sdist и установка wheel для smoke-проверки.
- Фактический CLI-сценарий `register → login → CRUD → JSON/XML → ZIP → audit`.
- Проверка структуры workflow; полный `act` запуск — только если Docker и `act` доступны.
- Финальное независимое ревью незакоммиченного diff.
